# Export QA Matrix — 2026-07-17 (C11 export-formats)

Real exports driven through the genuine renderer path (`RendererManager.exportProject`
→ `SceneExporter` → mediabunny/WebCodecs for video, clean-room `lib/export/gif` for GIF),
then probed with `ffprobe`/`ffmpeg` 8.1.2. Not a stub: driven on a dev build with
`NEXT_PUBLIC_E2E_STUB_EXPORT=0` (bridge `stubExport === false` asserted at run time).

## Method

- Seeded an anon project (default canvas **1920×1080**, 30 fps) and placed a single 1.0s
  text element (`content: "QA MATRIX"`) via the E2E bridge — a pure canvas render, so
  every produced file exercises the real encode loop + the contain-fit output stage
  without depending on video-decode availability in headless Chromium (see queue C9 /
  bug-purge-w2: bundled Chromium has no H.264/HEVC WebCodecs decode).
- For each row, called `editor.project.export({ options })` with the preset's
  `format` / `quality` / `dimensions`, wrote the returned buffer to disk, and probed it.
- `includeAudio: false`, `includeWatermark: false` for reproducibility.
- The scene is always **rendered** at the project canvas (1920×1080); a preset's
  `dimensions` only drive the final **output** canvas, onto which each frame is
  contain-fit blitted (uniform scale, centered, black letterbox/pillarbox). So a
  16:9 project exported at 9:16 is correctly pillar/letter-boxed, never recomposed.

## GIF notes (expected behavior, not defects)

- GIF header bytes verified `47 49 46 38 39 61` = `GIF89a`; the NETSCAPE2.0 loop
  application extension (`21 FF 0B … 01 00 00`, loop count 0 = infinite) is present
  immediately after the logical screen descriptor.
- **GIF duration probes as 0.900s for a 1.0s / 30 fps source.** GIF frame delays are
  integer **centiseconds**; `round(100/30) = 3 cs` per frame → 30 × 3 cs = 90 cs = 0.9s
  (effective 33.3 fps display cadence). This is inherent to the GIF format's timing
  resolution, not a drift in our encoder — every 30 fps GIF exhibits it. If exact
  wall-clock GIF duration ever matters, the lever is choosing a GIF-friendly fps
  (25 fps → 4 cs → exact; 20 fps → 5 cs → exact); documented here rather than "fixed".
- GIF is silent by design: the export dialog disables the audio control and labels it
  "Audio not available for GIF", and `RendererManager` skips the audio mixdown entirely
  for `format === "gif"`.

## Captions/SRT+VTT (C11-1)

Client-side serialization (`lib/subtitles/serialize.ts`) + timeline-time cue collection
(`lib/export/captions.ts`) replace the frozen-ai-backend round-trip. Round-trip validated
against the in-repo parsers (`parseSrt`/`parseVtt`) to millisecond precision (24 unit
tests). Timebase handling: timeline subtitle text elements export in timeline time
directly; transcript-store fallback maps asset-relative → timeline time through the
referencing element's trim window (`timelineT = startTime + (t − trimStart)`, clipped to
`[trimStart, trimStart+duration)`). Known limitation: the transcript store records no
asset linkage, so the fallback uses the first on-timeline media element (surfaced to the
user via the returned `source` discriminator); documented in `lib/export/captions.ts`.

  was not performed on a physical player; ffmpeg full-decode with zero errors is the
  machine-checkable proxy used here.
